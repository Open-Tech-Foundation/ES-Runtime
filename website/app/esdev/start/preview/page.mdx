# Previewing a release

The dev loop is not what ships: `NODE_ENV` is `"development"` and nothing is
hashed. `esdev preview` serves the **release** output, which is where failures
the dev loop is blind to show up — a package that hands over a different module
under `production`, or a `<link>` pointing at a name hashing changed.

```sh
esdev build
esdev preview            # → http://127.0.0.1:4173
esdev preview --dir=dist --port=5000
esdev preview --config=deploy/esdev.json   # the site another project file describes
```

Preview serves existing output; it does not build. Missing paths fall back to
`index.html` for client-side routes. Responses support `ETag` and
`Last-Modified` revalidation (`304`) and HTTP range requests (`206`, or `416`
when a range cannot be satisfied).

A server bundle has no static output to preview. Run it under `esrun`, as it
will run in production.

## Any static folder, no packages

`--dir` serves whatever folder you point it at — no project, no `esdev.json`,
no `npx serve` or `python3 -m http.server`. The folder needs an `index.html`
at its root; everything else is served as-is, with the same fallback,
validators, and ranges as above.

```sh
esdev preview --dir=./public        # → http://127.0.0.1:4173
esdev preview --dir=./dist --port=5000
```

Handy for a mock API's docs folder, a downloaded theme, or the `dist/` of a
tool that is not `esdev build` — anything with an entry document. Loopback
only, like every endpoint `esdev` opens; `Ctrl-C` stops it.

For the rebuild-and-reload workflow, return to [The dev loop](/esdev/start).
