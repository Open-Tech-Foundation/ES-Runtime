# esdev test

Find and run test files with the assertion vocabulary provided by
[`runtime:test`](/api/test). Both `.test.` and `.spec.` files are discovered
in the supported JavaScript and TypeScript extensions.

```sh
esdev test                    # every *.test.* and *.spec.*
esdev test math               # ...whose path contains "math"
esdev test --file=x.test.ts   # exactly one file
```

## JSX in tests

A test file may be `.jsx` or `.tsx`. Which JSX it is comes from the project's
[`jsx` section](/esdev/build/project#jsx), or from the file's own
`@jsxImportSource`/`@jsx` pragma. There is no default: JSX with nothing said
about it is refused rather than compiled for a framework nobody named.

```json
{ "jsx": { "importSource": "preact" } }
```

The same setting compiles the bundle, so a component means the same thing in a
test and in a build.

## DOM tests

Pass `--dom` to give each test file a fresh, in-memory DOM: `document`,
elements, events, forms, selectors, styles, custom elements, Shadow DOM and
`MutationObserver`. It is available to tests only; ordinary `esdev` runs do not
get these globals.

```sh
esdev test --dom
```

For a test that needs layout or anything else only a real browser has, run the
same file with `--browser`. See [DOM testing](/esdev/test/dom) and
[Browser testing](/esdev/test/browser).
