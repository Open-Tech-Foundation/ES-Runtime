# Writing a database driver or an ORM

The database layer has two audiences: driver authors who implement a backend and
ORM authors who build on the portable connection surface. These focused guides
separate the implementation contract from the data model and production traps.

## Database authoring guide

- [Driver shape and implementation](/docs/db/authoring/backend) — define a
  backend, handle messages, and run conformance.
- [Rows and value types](/docs/db/authoring/data) — map values without losing
  portability.
- [Production pitfalls and errors](/docs/db/authoring/production) — connection
  ownership, cancellation, caching, and failure behavior.
- [ORM integration and checklist](/docs/db/authoring/checklist) — what an ORM may
  rely on and the final implementation checklist.

Start with the [database API](/api/db) to see the contract drivers implement.
