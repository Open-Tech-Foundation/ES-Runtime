# Migrating from Bun

Bun's Web-standard surface carries over unchanged. What moves is the `Bun.*`
namespace: each ambient global becomes an explicit `runtime:` import.

### 1. File handling (`Bun.file`, `Bun.write`)

```js
// ❌ Bun
const text = await Bun.file("./data.txt").text();
const json = await Bun.file("./data.json").json();
await Bun.write("./out.txt", "data");

// ✅ esrun
import { file, write } from "runtime:fs";

const text = await file("./data.txt").text();
const json = await file("./data.json").json();
await write("./out.txt", "data");
```

### 2. Subprocesses (`Bun.spawn`, `Bun.$`)

```js
// ❌ Bun
const proc = Bun.spawn(["git", "rev-parse", "HEAD"]);
const text = await new Response(proc.stdout).text();

// ✅ esrun
import { Command } from "runtime:system";

const { stdout } = await new Command("git", {
  args: ["rev-parse", "HEAD"],
}).output();

const text = new TextDecoder().decode(stdout).trim();
```

### 3. Hashing and passwords (`Bun.hash`, `Bun.CryptoHasher`, `Bun.password`)

```js
// ❌ Bun
const key = Bun.hash(data);
const digest = new Bun.CryptoHasher("sha256").update("data").digest("hex");
const stored = await Bun.password.hash(input);

// ✅ esrun
import { hash, Hasher, password } from "runtime:hashing";

const key = hash("xxhash64", data);
const digest = new Hasher("sha256").update("data").digest("hex");
const stored = await password.hash(input);
```

### 4. Cookies (`Bun.Cookie`, `Bun.CookieMap`)

The same classes, imported from `runtime:http`. `request.cookies` works the same
way in `serve()`: changes are sent with the response.

```js
// ❌ Bun
Bun.serve({ fetch(req) { req.cookies.set("theme", "dark"); return new Response("ok"); } });
const cookie = new Bun.Cookie("sid", id, { httpOnly: true });

// ✅ esrun
import { serve, Cookie } from "runtime:http";

serve((req) => { req.cookies.set("theme", "dark"); return new Response("ok"); });
const cookie = new Cookie("sid", id, { httpOnly: true });
```

Output matches Bun's, with one intentional difference: a cookie a browser would
drop **throws** instead of being sent. That covers:

- `SameSite=None` or `Partitioned` without `secure`;
- a `__Host-`/`__Secure-` cookie that breaks its prefix rules;
- a fractional `maxAge`.

When you delete a `__Host-` or `__Secure-` cookie, pass
`{ secure: true }`. Otherwise the deletion is refused, where in Bun the browser
would have ignored it. `Cookie.parse` also decodes the value, as `CookieMap`
does in both runtimes.

### 5. Async context (`node:async_hooks`)

Bun's `AsyncLocalStorage` becomes [`runtime:context`](/api/context) — a rename,
with no `async_hooks` shim.

```js
// ❌ Bun
import { AsyncLocalStorage } from "node:async_hooks";
const store = new AsyncLocalStorage();
store.run({ tenant }, () => handle(req));
store.getStore().tenant;

// ✅ esrun
import { createContext } from "runtime:context";
const store = createContext({ name: "request" });
store.run({ tenant }, () => handle(req));
store.get().tenant;
```

| Bun | esrun |
| --- | --- |
| `new AsyncLocalStorage()` | `createContext({ name })` |
| `.getStore()` | `.get()` |
| `.run(store, fn)` | `.run(value, fn)` |
| `.enterWith()` | Removed — `snapshot()` |
| `AsyncResource` | Removed |

### 6. Observability and process metrics

```js
// ❌ Bun
process.memoryUsage().heapUsed;
process.cpuUsage().user;      // microseconds
import { heapStats } from "bun:jsc";

// ✅ esrun
import { memoryUsage, cpuTime, uptime } from "runtime:process";
import { metrics, subscribe } from "runtime:diagnostics";

memoryUsage().heapUsed;
cpuTime();                    // milliseconds, this agent's thread
metrics().gc.pauseMs.p99;     // needs --allow-diagnostics
```

| Bun | esrun | Needs |
| --- | --- | --- |
| `process.memoryUsage().heapUsed` | `memoryUsage().heapUsed` | — |
| `process.memoryUsage().rss` | `metrics().process.rss` | `diagnostics` |
| `process.cpuUsage()` `{ user, system }` | `cpuTime()` — one total | — |
| `bun:jsc` `heapStats()` | `metrics().gc` | `diagnostics` |
| `Bun.gc(true)` | Removed — no forced collection | — |
| `--console-depth`, ad-hoc tracing | `subscribe(filter, onBatch)` | `diagnostics` |
| OpenTelemetry SDK | `esrun --otel=<url>` | — |

Units and scope both change: milliseconds rather than microseconds, and the
per-agent figures describe the **calling agent** rather than the process — which
is what makes them answerable inside a worker. The process-wide ones are in
`metrics()`, behind `--allow-diagnostics`.

See the [Request context](/docs/guides/context) and
[Observing the runtime](/docs/guides/diagnostics) guides.
